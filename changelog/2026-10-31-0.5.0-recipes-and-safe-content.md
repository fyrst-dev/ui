# 0.5.0: config recipes, text-by-default content, one override API

**Date**: 2026-10-31

## What's Changed

0.5.0 acts on a code-quality and architecture review of 0.4.1. It is a breaking minor for consuming apps. Apps migrate with [`.agents/skills/fyrst-ui-0.5-migration/SKILL.md`](../.agents/skills/fyrst-ui-0.5-migration/SKILL.md). The release notes are in [`CHANGELOG.md`](../CHANGELOG.md); this file records the design decisions.

## Component styles are Panda config recipes

**Before.** Each component had a `styles.ts` with `cva` / `sva` and called `css(styles.raw(variants))` at runtime. Panda could not see the variants (`imported_recipe_raw_dynamic`, 9 warnings) or the dynamic `css()` calls (`panda_call_unextractable`, 41 warnings). Some controls built styles with runtime ternaries inside `css()`. The Progress percent scale was 101 hand-written variants.

**After.** Recipes live in `packages/preset/src/recipes/` and are registered by `componentsPreset` (`packages/preset/src/components.ts`). Components call the generated runtime from `styled-system/recipes`, which the build maps to `@fyrst/ui/recipes` (Rolldown `output.paths`, replacing a regex `renderChunk` plugin).

- **`staticCss` for every recipe.** Variants come from props at runtime, so Panda cannot see which ones are used. A spike against a packed tarball showed that without `staticCss` a consumer only gets the default variant. With it, every variant is generated. 0.4.x already shipped every component's CSS to every app (a Badge-only app got Progress classes), so this does not grow app CSS.
- **Not in the token preset.** `componentsPreset` only goes into the library's Panda config. `panda lib` bundles it into `dist/panda/preset.mjs` for `designSystem` apps. `@fyrst/ui/design-preset` stays token-only, so token-only apps do not get component CSS.
- **Generated variants.** A preset runs as code, so Progress `percent`, Loader `size`, and Card `borderSize` are built with `Object.fromEntries`.
- **Consumers can extend recipes** by key (`theme.extend.recipes.fyButton`). Panda merges the app's definition over the library's and logs `design_system_artifact_conflict`. Verified in `packages/nuxt/test/panda-lib.test.ts`.
- **Overrides.** `withCss(recipeClass, override)` appends `css(override)`. Overrides live in the `utilities` layer and recipes in `recipes`, so an override always wins.

### Layer pitfall found during verification

Panda emits recipe `base` styles in a sub-layer (`@layer recipes { @layer base { … } }`) below variants. So:

1. A variant beats any `base` state selector, whatever its specificity. Indeterminate Progress bars lost their `[data-state="indeterminate"]` width to `percent_0` and rendered at 0 px.
2. For `!important`, layer order inverts: `base` `_focus { borderColor: 'primary !important' }` beat the `valid=false` border, so a focused invalid field showed the primary border instead of red.

Both are fixed. `packages/components/test/recipes.test.ts` now fails on `!important` in any recipe `base`, and on any new overlap between a conditional `base` property and a variant that is not on a reviewed list.

## Content renders as text

Twelve `v-html` sites rendered props as HTML, with `vue/no-v-html` turned off. Field `error` / `message` often carry server or user text, which made them an XSS path. All content now goes through `internal/RichText.vue`: text by default, HTML only with the component's `html` prop. It is the single remaining `v-html`, and the lint rule is on again.

## One override API

Five override styles existed: `classRoot`/`classIcon`/…, `classes` (a class string), `classWrapper`/`classCarousel`, `classTrigger`, and `css` maps. Every component now takes `css: CssMap<slots>`. A test against a packed consumer confirmed that Panda extracts `css.raw({…})` but not a bare object literal. The 0.4.x playground passed bare objects to PricingCard, which produced no CSS. The docs and the migration skill now require `css.raw()`.

## Smaller structural changes

- `useFieldControl()` replaces seven copies of the id / `aria-describedby` / validity logic. The Field wrappers share `FieldSharedProps`, use `defineModel`, and render the footer through one `FieldFooter`.
- The carousel uses one typed `CarouselContextKey` instead of nine string `provide` keys. The unused `TabContextKey` is gone.
- `FlyoutRoot` uses Reka `PopoverRoot` / `PopoverTrigger` / `PopoverContent`. That brings in Escape handling, outside-click dismissal, `aria-controls`, and focus return. A capture-phase check pins a hover-opened flyout on click instead of toggling it closed.
- Semantic colors `surface`, `border`, and `text.muted` replace most `_light` blocks. `_light` stays where state selectors must beat light-mode colors on specificity (the switch track) and on per-variant color schemes (Button).
- `forceImportExtension: true` makes the published Panda runtime loadable in plain Node.
- Vitest runs codegen once in `globalSetup` instead of racing `panda codegen --clean` in every worker. The components' Panda config imports the preset source, so tests no longer need a preset build.
- Removed dead code: the empty `nuxt/src/index.ts` and `tsup.config.ts`, the preset's unused codegen, the Nuxt package's stale `release` script, stale ignore entries, and unreachable branches in `urlUtils`.

## Verification

- `bun run lint`, `bun run typecheck`, `bun run build`, `bun run test`: 75 component tests and 28 Nuxt / packed-consumer tests pass.
- The Nuxt playground builds, and every page SSR-renders with status 200.
- **Computed-style diff against 0.4.1.** Both playground builds ran side by side. Every element in the dark and light columns of 12 pages was compared on 19 properties, plus field rest / hover / focus states. Remaining differences: field helper text in light mode (intentional), PricingCard overrides that now apply (bug fix), and playground copy edits.
- **Flyout in Chromium.** Hover opens, moving into the panel keeps it open, leaving closes it, a click while hover-open pins it, and an outside click and Escape close it.
