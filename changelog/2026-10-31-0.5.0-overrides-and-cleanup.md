# 0.5.0: one override API and cleanup

**Date**: 2026-10-31

## What's Changed

0.5.0 acts on a code-quality and architecture review of 0.4.1. It is a breaking minor for consuming apps. Apps migrate with [`.agents/skills/fyrst-ui-0.5-migration/SKILL.md`](../.agents/skills/fyrst-ui-0.5-migration/SKILL.md). The release notes are in [`CHANGELOG.md`](../CHANGELOG.md); this file records the design decisions.

## Component styles stay atomic `cva` / `sva`

A pre-release of 0.5.0 moved component styles to Panda config recipes (`fy*`, classes like `fy-button--size_md`) in a library-only preset with `staticCss`. It worked: overrides won by cascade layer, apps could extend recipes, and repetitive variants could be generated in code. It was reverted before release, because it changes every component class name, which breaks app snapshots, test selectors, and any CSS that targets the library's atomic classes, and because Panda puts recipe `base` styles in a lower sub-layer than variants. That layering caused two regressions during verification (indeterminate Progress at 0 px, and a focused invalid field losing its red border).

0.5.0 keeps the 0.4.x model, with these changes:

- **One merge helper.** `withCss(style, override)` is `css(style, override)`. Components pass `styles.raw(…)` (or one slot of it). Merging the objects first gives one class per property, so the override wins. Appending an override class to a finished class string would leave both atomic classes on the element and let stylesheet order decide; that is what `AlertRoot` `classRoot` used to do. The single dynamic `css()` call lives in `internal/css.ts`, which takes `panda_call_unextractable` from 41 warnings to 2.
- **No runtime ternaries in `css()`.** Checkbox, radio, select, field chrome, the prompt form, the carousel, and the flyout had inline `css({ width: size === 'sm' ? … })` or `css(css.raw(…))` calls. They are `cva` / `sva` definitions now (`internal/controls/choiceStyles.ts`, `selectStyles.ts`, `Field/styles.ts`, `Form/styles.ts`, `Carousel/styles.ts`, `Flyout/styles.ts`), with disabled and invalid states expressed as `_disabled` / `_invalid` conditions.
- **Expected warnings.** Twelve `imported_recipe_raw_dynamic` warnings remain: `.raw()` is called with runtime variants in another file than the definition. Each definition still generates every variant, so they do not affect the CSS (same guidance as the Panda v2 skill, section 9). Moving the `.raw()` call into a helper next to each definition would silence them; it was left out to keep one pattern across components.
- **Static literals.** Panda reads `cva` / `sva` at build time, so the Progress `percent`, Loader `size`, and Card `borderSize` variants stay written out.

## Content stays HTML

A pre-release of 0.5.0 rendered content props as text and added an opt-in `html` prop, because field `error` / `message` often carry server or user text. That was reverted before release: rendering HTML is the documented contract, and sanitizing untrusted strings is the consuming app's responsibility, not the library's. The README now says which props render HTML and that apps must sanitize them (or use the slots, which Vue escapes). The only change kept is that `Button`'s `title` attribute strips tags from the label.

## One override API

Five override styles existed: `classRoot`/`classIcon`/…, `classes` (a class string), `classWrapper`/`classCarousel`, `classTrigger`, and `css` maps. Every component now takes `css: CssMap<slots>`. A test against a packed consumer confirmed that Panda extracts `css.raw({…})` but not a bare object literal. The 0.4.x playground passed bare objects to PricingCard, which produced no CSS. The docs and the migration skill now require `css.raw()`.

## Smaller structural changes

- `useFieldControl()` replaces seven copies of the id / `aria-describedby` / validity logic. The Field wrappers share `FieldSharedProps`, use `defineModel`, and render the footer through one `FieldFooter`.
- The carousel uses one typed `CarouselContextKey` instead of nine string `provide` keys. The unused `TabContextKey` is gone.
- `FlyoutRoot` uses Reka `PopoverRoot` / `PopoverTrigger` / `PopoverContent`. That brings in Escape handling, outside-click dismissal, `aria-controls`, and focus return. A capture-phase check pins a hover-opened flyout on click instead of toggling it closed.
- Semantic colors `surface`, `border`, and `text.muted` replace most `_light` blocks. `_light` stays where state selectors must beat light-mode colors on specificity (the switch track) and on per-variant color schemes (Button).
- `forceImportExtension: true` makes the published Panda runtime loadable in plain Node.
- Vitest runs codegen once in `globalSetup` instead of racing `panda codegen --clean` in every worker. The components' Panda config imports the preset source, so tests no longer need a preset build.
- Removed dead code: the empty `nuxt/src/index.ts` and `tsup.config.ts`, the preset's unused codegen, the Nuxt package's stale `release` script, stale ignore entries, and unreachable branches in `urlUtils`.

## Verification

- `bun run lint`, `bun run typecheck`, `bun run build`, `bun run test`: 74 component tests and 28 Nuxt / packed-consumer tests pass. A component test fails if `withCss` appends instead of merging (checked by breaking it on purpose).
- The Nuxt playground builds, and every page SSR-renders with status 200.
- **Computed-style diff against 0.4.1.** Both playground builds ran side by side. Every element in the dark and light columns of 12 pages was compared on 19 properties, plus field rest / hover / focus states. Remaining differences: field helper text in light mode (intentional), PricingCard overrides that now apply (bug fix), and playground copy edits. Field focus and hover states match 0.4.1 exactly.
- **Flyout in Chromium.** Hover opens, moving into the panel keeps it open, leaving closes it, a click while hover-open pins it, and an outside click and Escape close it.
